# 가입자 검수봇

독립 실행형 Telegram 전화번호 검수 접수/정산 서비스입니다. **GitHub 연결, 기존 서비스 의존성 없이** 실행할 수 있습니다.

> 주의: Telegram Bot API 자체는 임의 전화번호의 Telegram 가입 여부·최근 접속일을 조회하는 기능을 제공하지 않습니다. 실제 검수는 해당 정보를 제공할 권한이 있는 외부 API 제공업체의 공식 명세와 적법한 개인정보 처리 근거가 있어야 가능합니다. 이 패키지에는 가짜 검수 결과나 임의의 API URL이 없습니다.

## 설치

1. `cp .env.example .env` 후 `TELEGRAM_BOT_TOKEN`, `ADMIN_WEB_TOKEN`(길고 무작위인 값), `ADMIN_TELEGRAM_IDS`를 설정하세요.
2. `docker compose up -d --build` 실행. Docker가 없다면 Python 3.11+ 환경에서 `pip install -r requirements.txt && python run.py`.
3. 텔레그램 봇에 `/start`를 보내고 CSV/XLSX/XLS 파일을 첨부하세요. 봇이 수량·중복·오류·예상 비용을 계산합니다.
4. 관리자 웹: `http://localhost:8000/admin` (사용자명 `admin`, 비밀번호 `ADMIN_WEB_TOKEN`). 외부에서 사용할 때는 **반드시 HTTPS 리버스 프록시**와 접근 제한을 설정하세요.
5. 사용자 식별자는 Telegram user ID이며, 관리자 화면에서 참조값을 지정해 운영 잔액을 충전할 수 있습니다. **실제 결제/자동 충전 연동은 제공되지 않습니다.**

## 실제 검수 API 연결 전 필수 조치

- 실제 제공업체의 API 계약(인증 헤더, URL, 작업 생성/상태/결과 요청 및 필드)을 확인하세요.
- `api_contract.example.json`을 `api_contract.json`으로 복사한 후 *제공업체 문서에 적힌 값으로만* 수정하세요. 샘플의 빈 문자열은 실제 명세가 아닙니다.
- `.env`에 `TELEGRAM_CHECK_API_URL` (HTTPS) 및 `TELEGRAM_CHECK_API_KEY`를 설정하세요.
- `auth_header`, `auth_prefix`, 요청 `method`와 `path`, `phones_field`, `task_id_path`, `state_map`, 결과의 `rows_path`, `phone_field`, `joined_field`, UID/username/last_active 필드를 업체 문서 기준으로 설정합니다.
- 상태와 결과 endpoint의 `{task_id}`는 실제 API가 해당 형식일 때만 사용합니다. 제공업체가 본문 또는 쿼리 파라미터를 요구하면 어댑터를 업체 명세대로 수정해야 합니다.
- `last_active`는 **시간대 정보가 있는 ISO8601 날짜 문자열**로 들어오는 경우에만 1/3/7일 필터가 동작합니다. Unix 초, Unix 밀리초 또는 'recently' 등은 변환 규격을 협의하여 별도 구현해야 하며 임의 해석하지 않습니다.
- 가입 여부 문자열의 의미도 제공업체 원문을 그대로 표시하므로 한국어 의미 매핑은 검증 후 추가해야 합니다.
- 명세 파일이 불완전하면 검수 신청 및 비용 차감이 차단됩니다. 단순한 설정 완료는 외부 API 연결 성공을 의미하지 않습니다.

## 주요 정책

- 기본 **0.6원/건**. DB에는 소수점 오차 없이 **0.1원 단위 정수**를 기록합니다.
- 최소 5,000건 ~ 최대 1,000,000건. 설정은 관리자 페이지에서 변경 가능.
- 한국 휴대전화 01 계열 입력을 지원합니다. 임의로 복원할 수 없는 전화번호는 제외합니다.
- 유효번호만 과금하며 중복/잘못된 번호는 사전 제외됩니다.
- 외부 API 결과가 확정적으로 완료/실패/취소된 배치에 대해 결과 미반환 건을 미처리로 처리하고 100% 환불합니다. 재시도 중 또는 상태 미확인 건은 자동으로 환불하지 않습니다.
- 네트워크 장애 중 작업 생성 응답을 받지 못하면 `reconcile` 보류 상태로 전환합니다. 제공업체 중복 과금 방지를 위해 무조건 재요청하지 않습니다.
- 서버를 다시 시작해도 SQLite 데이터 및 작업 상태를 유지합니다. **단일 인스턴스/워커** 실행이 기본입니다.
- 결과 CSV는 UTF-8 BOM, Excel은 XLSX로 저장합니다. 결과에서 내부 외부 API 작업 ID는 제외합니다.

## 현재 포함 범위와 제약

구현: Telegram 파일 접수, CSV/XLS/XLSX 분석, 헤더 감지, 정규화, 중복 제거, 선결제 원장, 관리 충전, DB 원자 잔액 차감, 외부 API 어댑터 설정 검사, 분할 배치 생성, 작업 조회, 배치 상태 관리, 결과 저장, 누락 건 환불, CSV/Excel 다운로드, 접속일 필터(ISO8601), 관리자 요금/수량 변경, 감사 로그, Docker 실행.

미완료/연동 필요: 실제 API 규격 검증 및 라이브 테스트, 업체별 결과 필드·시간 단위 매핑, API의 고객별 이용·과금 정책 반영, 외부 결제사 연동, 수동 재처리/환불 승인 UI, 대용량 성능 실측(100만 건), 데이터 보관 기한 자동 파기, 세분화된 관리자 권한, API 이용 약관·개인정보법 적합성 검토. **프로덕션 완성/실 API 연결 성공을 주장하지 않습니다.**

중요: 현재 작업 생성 요청은 제공업체 API에 멱등성 헤더를 전달하지 않습니다. 타임아웃/유실 시 보류하여 중복 생성 위험을 낮추지만 제공업체가 멱등키를 지원한다면 명세에 맞게 추가해야 합니다. 현재 워커는 주기당 생성 1건·상태 확인 1건 수준의 보수적 처리로 대량 작업 성능 최적화가 필요합니다.

## 개인정보·운영 보안

동의·정당한 법적 근거가 있는 번호만 처리하세요. 서버 관리자 외에는 원본 업로드 및 DB 파일에 접근할 수 없도록 파일시스템을 보호하세요. 개인정보는 디스크에 평문으로 보관되므로 **암호화 저장소·백업 암호화·보관기한 만료 삭제·관리자 IP 제한·비정상 접근 감시**를 추가하기 전에는 민감한 실제 운영 데이터 투입을 권장하지 않습니다. `WEB_BASE_URL`은 현재 참고용이며 별도 사용자 웹 앱은 없습니다. Telegram 사용자 소유권 확인은 봇 사용자 ID로 합니다.

## 신규 기능: 회원가입 · USDT TRC-20 자동충전 · 관리자 결과 증빙

- `/register`, `/login`, `/` 웹 회원 가입과 로그인, 파일 업로드, 잔액/신청 내역/결과 파일 메뉴를 제공합니다. 비밀번호는 scrypt 해시로 저장하고 7일 HttpOnly 세션을 사용합니다. 운영 시 TLS/HTTPS는 필수입니다.
- `/admin`에서 회원별 **고유 TRON 입금주소**를 지정합니다. 주소는 운영자가 직접 통제하는 **실제 입금주소**여야 하며, 이 프로그램은 개인키를 생성·보관하거나 지급하지 않습니다. 같은 주소를 다른 회원에게 재사용할 수 없습니다. 등록 시점 **이후** 들어온 입금만 인정합니다. 주소의 소유권을 API로 확인하지 않으므로 배정 전 반드시 지갑에서 대조하세요.
- 환경변수 `TRONGRID_API_KEY`가 있고 관리자가 `/admin`에서 `1 USDT → KRW` 환산 단가(정수 원)를 설정하면, TRON 메인넷 TRC-20 **USDT**의 확인된 수신 이체만 조회하여 원화 지갑 잔액으로 자동 환산합니다. TRX 자체 이체는 충전 대상으로 처리하지 않습니다. 환율 0원 또는 API키 미설정 시 자동 지급하지 않습니다. 시장 환율이 아닌 운영자가 설정한 **고정 환산 단가**입니다. 실제 환율 자동 갱신 기능은 포함되지 않았습니다.
- 거래 `txid`와 환산 단가, 입금 USDT 수량, 지급 원화, 원장 참조키를 저장합니다. txid별 단 한번만 충전되도록 DB 유니크 인덱스와 트랜잭션을 사용합니다. TRC-20 다중 로그가 단일 txid에 존재하는 특수 거래는 자동으로 여러 번 인정되지 않아 수동 대조가 필요합니다.
- TronGrid에서 `only_confirmed=true`로 응답한 이체만 사용합니다. RPC 장애, 요청 제한, 주소 배정 오류, 누락된 과거 이력 및 API 페이지 한도 시에는 자동 충전이 지연되거나 누락될 수 있으므로 운영 전 블록 탐색기와 거래 원장 대조 테스트가 필요합니다.
- 검수가 완료되면 `result_archives`에 검수 결과의 canonical SHA-256 지문을 저장합니다. **구매자와 관리자는 동일 DB의 원본 결과를 조회하고 별도 권한 검증 후 CSV/XLSX를 다운로드**합니다. 관리자 상세 페이지에서 다운로드하고 다운로드 시각을 기록합니다. 관리자 Telegram ID(`ADMIN_TELEGRAM_IDS`)가 설정되어 있고 봇 대화를 먼저 시작한 관리자에게 결과 CSV 파일을 자동 발송하며, 45MB 초과 시 관리 화면에서 내려받도록 알림만 발송합니다. 전달에 실패하면 다시 시도합니다. 스토리지의 백업·불변 보관은 배포 환경에서 별도로 구성해야 합니다.
- Telegram 봇 로그인은 기존 Telegram ID를 계속 사용합니다. 웹 계정은 독립된 ID와 지갑으로 분리되어 있으며 **같은 사용자가 두 채널을 쓰더라도 자동 합산되지는 않습니다.** 계정 연동은 별도 인증 설계가 필요합니다.

### 배포 전 필수 검증

HTTPS 리버스 프록시, 관리자 Basic Auth 비밀번호, 비밀번호 분실/계정 복구 정책, 로그인 속도 제한, CSRF 방어를 강화해야 합니다. 단일 서버 SQLite 실행을 기본으로 하며 다중 프로세스/다중 인스턴스 배포를 지원하지 않습니다. 입금 모니터링은 TronGrid 제공 결과를 기준으로 구현한 초기 버전으로서 **실자산을 수취하기 전에 소액 충전·중복 이체·입금 누락·페이지네이션·장애 복구를 현장 검증**하세요. 외부 검수 API는 종전대로 실제 명세가 제공되기 전에는 신청과 청구를 차단합니다.


## 출시 전 운영 체크리스트 (필수)

이 배포 패키지는 외부 서비스를 실제 연동하지 않은 **설정 대기형 소스코드**입니다.
코드 테스트 통과와 실서비스 금융/개인정보 운영 안전성은 별개입니다.

- 서버: HTTPS 리버스 프록시, 방화벽, 백업, 모니터링 및 단일 워커로 운영. SQLite 공유 네트워크 볼륨 금지.
- 관리자: `ADMIN_WEB_TOKEN` 강력한 비밀번호 사용, 관리자 접근 IP 제한 및 HTTPS 적용. 관리자 브라우저에는 HTTP Basic 인증이 유지됩니다.
- 검수 API: 실제 계약서에 따라 `api_contract.json` 완성 후 소량 테스트, 누락/부분 성공/요금 규칙 검증. 문서 없이는 신청 불가.
- 입금: 독점적으로 통제하는 고객별 TRON 주소 사용. `TRONGRID_API_KEY`, 수동 환율, 확인 거래 조회 테스트 후 실제 자금 사용. 같은 TXID에서 복수 Transfer 발생 시 수동 검증 대상입니다.
- 실제 출금/송금 자동화는 제공하지 않습니다. 회원 충전은 원화 서비스 크레딧 장부에 반영됩니다.
- 결과의 관리자 전달은 관리자 지정 Telegram 계정에 전송됩니다. 민감한 고객 개인정보 공유 경로이므로 권한자만 지정하고 파일 보관/삭제 정책을 적용하세요.
- 파일/DB는 암호화된 볼륨, 접근제어, 정기 백업 필요. `RESULT_RETENTION_DAYS`는 보관 정책 값이며 자동 영구 삭제 작업은 **아직 포함되어 있지 않습니다**.
- 서비스 이용약관, 개인정보 수집·제공 동의, 법률상 적법한 전화번호 검수 권한과 규제사항을 실제 운영 전에 검토하세요.
- 보안: 사용자 로그인 시도 횟수 제한, 관리자 다중 인증, 업로드 악성 파일 검사 및 리버스 프록시 rate-limit은 배포환경에서 별도 설정해야 합니다.

### 외부 작업 결과 불명 복구

관리자 `/admin` 페이지의 대조 메뉴를 통해 `reconcile` 배치에 외부 작업 ID를 연결해 재개하거나, 제공업체에 실제 작업이 생성되지 않았음을 확인한 후 실패로 확정할 수 있습니다. 외부 상태가 불명확한 배치를 임의로 실패 확정하면 이중 제공/부정확 정산 위험이 있습니다.

## UI 및 관리자 회원관리 추가 안내

- 텔레그램 `/start`: 계정 현황·검수 단가·검수 방법을 간결한 메뉴로 안내합니다.
- 지원 입력 파일: XLSX/XLS/CSV/TXT. TXT는 줄당 전화번호 하나를 사용하고 UTF-8 또는 CP949를 허용합니다.
- `8210-1234-5678`, `+821012345678` 및 `010-1234-5678`은 동일한 `01012345678`로 인식하여 중복을 제거합니다. 잘못된 번호는 추측 변환하지 않습니다.
- 결과 기본값은 XLSX이며 번호 표시 형식은 `010-1234-5678`입니다. 이전 CSV 내보내기 API는 호환성을 위해 유지합니다.
- 관리자: `/admin/members`에서 회원 검색·페이지 이동, `/admin/member/{회원ID}`에서 잔액, 검수 작업, USDT 입금, 정산원장, 활동 감사 로그를 확인합니다.

## TRON TRX / USDT(TRC-20) 자동충전 (추가)
- Telegram 메뉴 `💳 잔액 · 충전` 에서 두 자산의 환율과 회원 전용 TRON 주소 확인.
- 관리자 `/admin`에서 회원별 고유 TRON 주소를 배정하고 TRX·USDT의 **원화 환산 단가**를 각각 설정(0원일 때 해당 자산 자동 반영 중지).
- TronGrid의 confirmed 거래 조회를 통해 일반 TRX `TransferContract` 및 공식 USDT TRC-20 컨트랙트의 입금을 확인, 동일 TXID 중복 잔액 적립 방지.
- TRX와 USDT 원본 수량은 1,000,000분의 1 단위로 보존하며, 표시할 때 **소수점 셋째 자리**로 반올림. **원화 잔액 정산은 기존 0.1원 단위**를 유지함.
- **주의:** 관리자에게 실소유·관리 지갑의 *회원별 고유 주소*를 배정받아야 작동하며, TronGrid 키와 해당 자산 환율이 설정되어야 실제 입금 반영됨. 비밀키는 프로그램에 입력하지 않음. 기존 주소의 과거 입금은 소급 처리하지 않음.
- 한 TX 내 복수 USDT 전송 등 모호한 이벤트는 추가 거래 대조가 필요할 수 있음. 실제 운영 전에 TronGrid 실입금 통합 테스트와 관리자 정산 감사를 실시할 것.

## Railway 자동충전 최종 설정 (TRX + USDT TRC-20)

Railway > Service > Variables에 다음 키를 입력하세요. 비밀키(private key) 또는 시드 구문은 **절대** 넣지 마세요.

```env
TELEGRAM_BOT_TOKEN=발급받은_텔레그램_토큰
ADMIN_TELEGRAM_IDS=관리자_텔레그램_숫자_ID
ADMIN_WEB_TOKEN=길고_무작위인_관리자_비밀번호
WEB_BASE_URL=https://실제_railway_도메인
TRONGRID_API_KEY=TronGrid_발급_API_키
TRONGRID_URL=https://api.trongrid.io
DEPOSIT_POLL_SECONDS=120
TRON_DEPOSIT_ADDRESSES=운영자가_실제_통제하는_서로_다른_TRON_주소_1,주소_2,주소_3
DATABASE_PATH=/data/checker.sqlite3
STORAGE_PATH=/data/uploads
CUSTOMER_SUPPORT=@teleck777
```

- `TRON_DEPOSIT_ADDRESSES`는 **선택** 환경변수입니다. 운영자가 통제하는 주소를 콤마로 구분해 미리 준비하면 고객이 충전 화면을 처음 열 때 미배정 주소가 자동 할당됩니다. 주소가 고갈되면 신규 사용자에게 충전 준비 중으로 표시됩니다. 주소는 재사용하지 않습니다. 기존 관리자 수동 주소 등록도 사용 가능합니다.
- 주소만 알아서는 해당 지갑의 자금을 출금할 수 없습니다. 주소 개인키는 별도 안전한 지갑에서 운영자가 관리해야 합니다. 지갑 생성이나 자산 이체/회수 기능은 없습니다.
- **중요:** 위 주소 풀의 실제 소유권은 API만으로 증명되지 않습니다. 운영자가 검증한 주소만 넣으세요. 풀에는 USDT 토큰 컨트랙트 주소를 넣지 마세요.
- `/admin`에서 **TRX 1개당 원화**와 **USDT 1개당 원화** 환산 단가를 각각 설정해야 합니다. 단가가 0이면 해당 코인은 적립하지 않습니다. 고정 환산 단가이며 자동 시세 연동이 아닙니다.
- TronGrid API로 `only_confirmed=true` 입금 기록을 120초 간격으로 조회합니다. 같은 txid는 재적립하지 않으며 사용자 원장에 기록됩니다. 원본 코인 수량은 6자리, 표시 수량은 3자리입니다.
- **Railway 영구 볼륨은 필수입니다.** `/data` 위치에 Volume을 마운트하고 서비스를 **단일 인스턴스**로 실행하세요. 볼륨 미설정이면 배포 시 원장이 유실될 수 있습니다.
- 실입금을 받기 전에 테스트넷이 아닌 실제 TRON 메인넷에서 *본인이 소유한 고유 주소*로 TRX와 USDT 소액을 각각 전송해 정확한 입금 및 중복 부재를 확인하세요. 이는 실운영 검증이 끝났다는 의미가 아닙니다.


## Google Sheets 환율 · USDT(TRC-20) 전용 충전

1. 새 구글 스프레드시트의 **A1**에 `=GOOGLEFINANCE("CURRENCY:USDKRW")` 입력 (구글 USD/KRW 기준, USDT 실거래 시세와 다를 수 있음).
2. 시트 **파일 → 공유 → 웹에 게시**에서 현재 시트를 CSV로 게시. 그 CSV 링크를 `GOOGLE_SHEET_CSV_URL` 환경변수에 입력. **외부에서 공개되는 시트에 개인정보를 넣지 마세요.**
3. Railway에 `TRONGRID_API_KEY`, 실제 운영 통제하의 고유 주소 목록 `TRON_DEPOSIT_ADDRESSES`, `GOOGLE_SHEET_CSV_URL` 설정.
4. Google 환율은 2분마다 갱신되며 10분 이상 갱신되지 않으면 신규 입금 적립을 보류합니다. 시트가 숫자 형식으로 A1 한 칸만 반환하는지 확인하세요.
5. TRX 입금은 자동 지급되지 않으며, 원화 잔액 자동충전은 **USDT(TRC-20)**만 지원합니다. 주소 배정 후 기존 입금은 자동 적립하지 않습니다. 환율은 확인된 시점의 시트 값으로 고정 기록됩니다.
6. 실제 입금 전에 메인넷 소액 검증 및 Volume 영구 보관, 관리자 접근 통제 확인이 필요합니다.

## 2026-10-16 통합 업데이트 — 충전주소 일원화 / 기존 검수 API 연동 후보

- 주소 목록은 관리자 `/admin`의 **주소 풀에 추가** 양식에서 등록한다. `TRON_DEPOSIT_ADDRESSES` 환경변수는 **폐기**되었다.
- 회원이 충전 화면에 접속하면 사용되지 않은 등록 주소를 트랜잭션 내에서 배정한다. 주소는 재활용하지 않으며 기존 배정 내역은 유지된다. 등록하는 주소는 운영자가 통제하는 수신주소여야 한다.
- USDT TRC-20 입금만 자동 적립한다. TRX 입금은 적립하지 않는다. 환율은 `GOOGLE_SHEET_CSV_URL`의 USD/KRW 값을 사용한다. 실제 USDT 현물 시장 가격과 다를 수 있다.
- 이전 연동 기록에서 회수한 API 경로 `POST /addTask`, `GET /checkTask?id=...`, `GET /exportPhone?id=...`, 헤더 `token`, 국가 필드 `conuntry` 후보를 `api_contract.legacy-template.json`에 추가했다.
- **중요: 작업 생성 body의 `phone_numbers`, 생성 응답의 `id`, 상태 응답의 `status`, 결과 CSV 열 이름과 상태 값 매핑은 공식 명세/실응답으로 검증되지 않았다.** 제공업체와 소량 테스트로 확인 후 명세 파일을 고쳐야 한다. `TG_API_CONTRACT_VERIFIED=0` (기본)에서는 검수 신청 및 비용 차감이 차단된다. 검증하고 나서만 `=1`로 활성화한다. 이 패키지는 외부 API의 정상 동작을 보증하지 않는다.
- 환경변수: `TELEGRAM_CHECK_API_URL=https://api.ftm111.pw/api/tg`, `TELEGRAM_CHECK_API_KEY=<비밀>`, `API_CONTRACT_FILE=./api_contract.legacy-template.json`, `TG_API_CONTRACT_VERIFIED=0`, `TRONGRID_API_KEY=<비밀>`, `GOOGLE_SHEET_CSV_URL=<공개 CSV URL>`, 기존 봇/관리자/DB 변수.
- 새 테이블 `deposit_address_pool`은 기존 SQLite DB에 `CREATE TABLE IF NOT EXISTS`로 추가된다. 기존 Volume의 DB를 절대 삭제하거나 교체하지 말 것. 운영 전 백업 필수.
- 자동 테스트는 제공업체 실제 서버/실입금 없이 로컬 단위 테스트로만 수행됨. 통합 검증이 끝나기 전 실자산 충전 및 유료 검수 운영 금지.


## 검수 API 일수 구간 필터 (2026-10-16)
- API의 `telegram_active`는 날짜/시간이 아니라 `1일 이내`, `3일 이내`, `7일 이내` 같은 **구간 문자열**로 판정합니다.
- 구매자가 `1일` 선택: 1일 이내만, `3일`: 1일+3일, `7일`: 1일+3일+7일, `전체`: 가입 확인된 모든 결과를 포함합니다.
- 날짜 문자열이나 미확인 구간은 임의 변환하지 않으며, 기간 필터에서는 제외합니다.
- 가입 여부가 명확하게 true/가입 등으로 확인되지 않은 건은 구매자 결과에서 제외합니다. 업체 반환 필드 의미가 다르면 실제 응답 확인 후 명시적으로 매핑해야 합니다.
- 관리자에게 Telegram으로 전송하는 Excel은 **검수 원본 전체(미가입 포함)**이며, 관리자 다운로드에서 `?days=raw`로 동일 데이터를 확인할 수 있습니다. 고객용 엔드포인트에서 `raw`는 금지됩니다.
- `TG_API_COUNTRY=KR`을 Railway 환경변수에 설정할 수 있으며 레거시 API 요청 필드는 기존처럼 `conuntry`로 유지합니다.
- 검수 API 실제 응답 검증 전 `TG_API_CONTRACT_VERIFIED=0` 유지, 임의로 1로 변경하지 마세요.
